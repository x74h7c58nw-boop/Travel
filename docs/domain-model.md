# 초기 데이터 모델

이 문서는 서비스의 장기 개념 모델입니다. 현재 구현은 그룹당 여행 하나이며 Trip·Settlement 테이블을 별도로 만들지 않습니다. 그룹·정산 테이블과 권한은 [그룹·정산 설계](groups-settlement-design.md) 및 해당 SQL 마이그레이션, 인증·사진·앨범 테이블과 권한은 [인증·앨범 구현 및 연동 계약](auth-albums-implementation.md) 및 해당 SQL 마이그레이션을 기준으로 합니다.

| 개념 | 역할 | 주요 관계 |
| --- | --- | --- |
| User | 서비스 사용자 | 여러 그룹에 참여 |
| Group | 여행원 모임 | 구성원과 여행을 관리 |
| Membership | 그룹 구성원과 역할 | 사용자와 그룹을 연결 |
| Invitation | 초대 및 수락 상태 | 그룹에 연결 |
| Trip | 여행지와 시작일·종료일 | 그룹에 연결 |
| Expense | 결제자·금액·통화·사용일·항목 | 여행과 결제자에 연결 |
| ExpenseShare | 여행원별 분담 금액 | 결제 내역과 분담자를 연결 |
| Settlement | 특정 시점의 최종 정산 결과 | 여행에 연결 |
| SettlementTransfer | 송금자·수신자·송금 금액 | 정산 결과에 연결 |
| Photo | 업로더·저장 위치·촬영 시각 | 여행과 업로더에 연결 |
| Album | 여행 사진으로 만든 앨범 | 여행에 연결 |
| AlbumPhoto | 앨범에 포함할 사진과 순서 | 앨범과 사진을 연결 |
| Post | 앨범 게시와 공개 범위 | 앨범과 게시자에 연결 |

## 사진·앨범 테이블 소유권

- `photos`, `albums`, `album_photos`는 인증·앨범 작업이 소유합니다.
- 그룹 작업이 제공할 `groups(id)`를 `photos.group_id`, `albums.group_id`가 참조합니다.
- `group_members(group_id, user_id)` 멤버십으로 그룹 접근을 판정합니다. 그룹 테이블과 해당 권한 정책은 그룹 작업 소유입니다.
- `photos.uploaded_by`, `albums.created_by`는 Supabase Auth의 `auth.users.id`를 참조합니다.
- 앨범 사진 연결은 DB 함수에서 사진과 앨범의 `group_id`가 같은지 검증합니다. 순서 0의 사진이 앨범 표지입니다.
- PostgreSQL RLS와 비공개 Storage 정책이 구성원 범위를 서버에서 강제합니다. UI의 숨김 처리는 권한 검사를 대신하지 않습니다.

## 정산 규칙 초안

- 개인별 순잔액 = 결제한 총액 − 부담할 총액
- 순잔액이 양수이면 받을 사람, 음수이면 보낼 사람입니다.
- 송금 안내를 모두 적용한 후 각 여행원의 순잔액은 0이 되어야 합니다.
- 금액은 통화별 최소 단위의 정수로 다뤄 부동소수점 오차를 방지합니다.
- 여러 통화는 환산 정책을 정하기 전까지 그대로 합산하지 않습니다.
- 정산 확정 시 계산에 사용한 결제와 분담 내역을 식별할 수 있어야 합니다.

## 접근 권한 초안

- 여행의 결제 내역과 원본 사진은 그룹 구성원에게만 제공합니다.
- 게시물 공개가 원본 사진 전체나 결제 내역 공개로 이어지지 않도록 구분합니다.
- 그룹 관리 권한과 사진·앨범·게시물 수정 권한은 구현 전에 구체화합니다.
