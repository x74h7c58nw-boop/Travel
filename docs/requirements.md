# 기능 요구사항

## 기본 흐름

1. 사용자가 여행 그룹을 생성합니다.
2. 초대를 받은 여행원이 그룹에 참여합니다.
3. 여행지와 시작일·종료일을 설정합니다.
4. 여행 중 결제 내역과 사진을 등록합니다.
5. 최종 정산 결과로 누가 누구에게 얼마를 보내야 하는지 확인합니다.
6. 사진으로 앨범을 만들고 여행원에게 공유하거나 게시합니다.

## 그룹과 여행

- 그룹 생성 및 여행원 목록 조회
- 초대 발급 및 초대 수락
- 여행지와 날짜 등록·수정
- 그룹 구성원만 여행의 비공개 데이터에 접근

## 결제 내역과 정산

- 결제자, 금액, 통화, 사용일, 항목, 분담 대상 등록
- 결제 내역 조회·수정·삭제
- 결제자와 비용을 분담하는 여행원 구분
- 결제 내역을 합산해 여행원별 낸 금액과 부담액 계산
- 최종 정산 시 송금자·수신자·금액 안내
- 전체 부담액과 결제 총액이 일치하도록 반올림 잔액 처리
- 실제 송금 기능은 별도 결정하며 초기 범위는 송금 안내

## 사진과 앨범

- 여행원이 사진을 업로드하고 여행별로 모아 보기
- 업로드한 사진을 바탕으로 앨범 생성
- 앨범 구성·정렬 방식과 자동 제작 수준은 추후 결정
- 여행원끼리 앨범 공유
- 앨범을 게시물로 발행하고 공개 범위 설정
- 여행원 공유와 공개 게시 권한을 구분하고 공개는 명시적으로 선택

## 기술 및 범위 결정

- 웹 우선, Next.js + TypeScript를 사용합니다.
- 인증과 사용자 식별은 Supabase Auth를 사용하고, 사용자 ID는 `auth.users.id`입니다.
- 초기 데이터 API는 별도 서버 없이 Supabase 클라이언트로 접근합니다.
- 영구 저장은 Supabase PostgreSQL, 사진 파일은 비공개 Supabase Storage, 그룹 내 변경 알림은 Supabase Realtime을 사용합니다.
- 비밀 값은 저장소에 커밋하지 않습니다. 앱 환경변수 이름은 `apps/web/.env.example`에 있습니다.
- 화면의 로그인 제한은 UX 용도이며 실제 그룹별 접근 제한은 PostgreSQL RLS와 Storage 정책으로 강제합니다.
- 그룹 생성·초대·멤버십은 팀원이 소유하며 사진·앨범 기능은 `groups(id)`와 `group_members(group_id, user_id)` 계약을 사용합니다.

## 후속 결정 사항

- 그룹 하나에서 여러 여행을 관리할지 여부
- 균등 분담만 지원할지, 개별 금액·비율 분담도 지원할지
- 단일 통화 또는 여러 통화 지원 여부와 환율 기준
- 정산 확정 이후 결제 내역 변경과 재정산 정책
- 사진 보관·보존 기간 정책
- 앨범 자동 제작 방식과 게시 공개 범위

첫 버전 사진 업로드는 JPEG/PNG/WebP, 파일당 최대 10MB로 제한합니다. 앨범 표지는 첫 번째 순서 사진으로 정하며, AI 자동 편집·인쇄용 파일·공개 SNS 피드는 후속 범위입니다.
